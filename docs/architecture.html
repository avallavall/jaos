Why this shape.

Two readers converge on one validating loader, so every model in memory passed the same checks. check.c has no edge into the solver: it reads the model as loaded, with no scaling and no solver state. That independence is the point of the checker (D18). status.c sets nothing; every status is set in simplex.c, presolve.c or model.c.

Three API rules the diagram cannot show.

Results are readable only at JAOS_SOLVE_OPTIMAL: a stale answer is an error, never a number. Any mutation discards the answer, but the stored basis survives mutation, which is what makes warm re-solve automatic (D68). Settings survive a load, so set → read → solve works.

Why each stage exists.

Presolve first: it removes what no iteration should pay for, and can prove infeasibility or unboundedness before any factorization exists. It reads the model through a const pointer.

Scaling uses exact powers of two, so applying a factor is exact in IEEE arithmetic; that is what bit-identical results require (D8). The stored matrix is never modified; the solver works on a scaled copy.

The slack basis is the cold start because its steepest-edge weights are exactly 1.0. A crash basis was measured and refused for destroying them (SPECS §3).

Publish is the single unscale point, and it normalises −0.0 to 0.0 so byte-for-byte digest comparison stays a valid no-op instrument (D21).

4 · The dual simplex loop and the LU

A bounded-variable dual simplex on M z = 0 with M = [A | −I]: every row gets a logical, so rows and columns are one kind of object. There is no separate phase 1. Dual feasibility is bought at basis construction (artificial bounds lent to free columns) and maintained by cost shifting; every loan is repaid before any verdict.

The run loop

flowchart TD
    A["refresh — factorize, compute x_B and duals"] --> L{"limits?"}
    L -- "work / time / callback stop" --> X1["WORK_LIMIT / TIME_LIMIT / INTERRUPTED"]
    L -- no --> RF{"needs_refactor?"}
    RF -- yes --> RD["refresh"] --> PR
    RF -- no --> PR["price_row — dual steepest edge,
pick the most violated basic (row r)"]
    PR -- "no violation" --> V1{"verified?"}
    V1 -- "no — refresh with refinement,
price again" --> PR
    V1 -- yes --> OPT["OPTIMAL"]
    PR -- "row r" --> PS["price_and_select:
BTRAN row r of B⁻¹ (rho) ·
alpha = rho·M by rows ·
dual ratio test"]
    PS -- "no entering column" --> V2{"verified?"}
    V2 -- "no — refresh with refinement,
price again" --> PR
    V2 -- yes --> INF["INFEASIBLE
(dual unbounded)"]
    PS -- "column q" --> PV["pivot(r, q)"]
    PV -- "declined — factorization
stopped agreeing (D86)" --> RF
    PV -- "taken — iters++" --> L
The verified rule (D20, D39).

Neither OPTIMAL nor INFEASIBLE is ever declared on carried numbers. The first time pricing finds nothing, the factorization is rebuilt with iterative refinement and the question is asked again. Only a repeat of the same answer on fresh numbers becomes a verdict. Every basis change clears verified.

One iteration

sequenceDiagram
    participant R as run
    participant P as pricing
    participant LU as lu.c
    participant T as ratio test
    participant V as pivot

    R->>P: price_row — score viol²/weight per basic, DSE
    P-->>R: leaving row r, side (below/above)
    R->>LU: BTRAN — rho = row r of B⁻¹ (sparse, DFS pattern)
    R->>P: price_all — alpha = rho·M, walking matrix rows in rho's pattern
    R->>T: dual_ratio_test — Harris two passes + bound flips (BFRT)
    T->>T: pass 1 — tightest ratio window (dual_tol slack)
    T->>T: pass 2 — largest pivot inside the window
    T->>LU: one FTRAN for all flipped bounds together
    T-->>R: entering column q, dual step theta
    R->>V: pivot(r, q)
    V->>LU: FTRAN — entering column B⁻¹ a_q
    V->>V: stability check — BTRAN's alpha_q vs FTRAN's col[r]
    alt disagree past LU_AGREE_TOL (and updates exist)
        V-->>R: decline pivot, needs_refactor, nothing mutated, no iteration billed
    else agree
        V->>V: dual update over alpha's pattern + cost shifts
        V->>LU: second FTRAN — tau for the exact DSE recurrence
        V->>V: update weights (reset all to 1.0 on drift), x_B, basis swap
        V->>LU: jm_lu_update — Forrest–Tomlin (or flag refactor at the interval)
    end
Why the stability check is free (D86).

The pivot element is computed twice anyway: once by BTRAN, once by FTRAN. In exact arithmetic they are equal. When they drift apart, the factorization no longer describes the basis, and pivoting on it is what produced pilot87's stall (D72). The declined pivot mutates nothing and is not billed.

When the factorization is rebuilt

triggerwhere
update count reaches REFACTOR_EVERYpivot, before the update
a Forrest–Tomlin update fails (numerical or memory)pivot — absorbed into a scheduled rebuild
BTRAN/FTRAN pivot disagreement past LU_AGREE_TOLpivot, declining the iteration (D86)
a verdict needs verifyingrun, with iterative refinement (D20/D39)
re-entry and restore pathsreenter_after_settling

There is no fill-based trigger. refresh also repairs a singular basis: up to REPAIR_ATTEMPTS rounds of patching uncovered rows with logicals, then the solve is abandoned as NUMERICAL_ERROR. The LU: Markowitz cost (r−1)(c−1) with threshold pivoting and an early-stopping pivot search (D46); Forrest–Tomlin updates; FTRAN/BTRAN report sparsity patterns and BTRAN's U-solve walks only the DFS-reachable slots (D38/D44).

Degeneracy: the Bland fallback

stateDiagram-v2
    DSE: normal pricing (DSE + Harris + bound flips)
    BLAND: Bland's rule (lowest index, exact min ratio, no flips)
    [*] --> DSE
    DSE --> BLAND: no infeasibility improvement for STALL_FACTOR·(rows+cols+1) iterations
    BLAND --> DSE: total infeasibility improves on the best seen
Why a fallback and not the default (D26).

Bland's rule terminates but crawls. It runs only while progress is provably stopped; progress is measured as total primal infeasibility, accumulated for free during pricing.

Three nested loops share the iteration counter

flowchart TD
    subgraph RE["reenter_after_settling — bounded rounds after the first OPTIMAL"]

After the first OPTIMAL, settle_shifts repays every cost loan; repaying can re-open dual infeasibility, so re-entry runs more rounds, keeps the best point seen (dual-feasible first, then lowest objective, D89) and can roll back to it. One sanity cap covers all three loops.

5 · Presolve and postsolve

flowchart TD
    START["jm_presolve_run
(reads the model const — never writes it)"] --> RL{"round loop

    RL --> A["row pass

    A --> B["column pass

    B --> CP["activity pass (rows with degree ≥ 2)

    CP --> RL
    RL -- done --> FR["frozen-row feasibility test
(once, after the loop)"]
    FR --> CO["compaction
build index maps, copy the reduced model,
carry the warm basis across"]
    CO --> OUT{"outcome"}
    OUT -- "nothing removed" --> N["NONE — no reduced model built"]
    OUT -- "columns remain" --> R["REDUCED — solver runs on the copy"]
    OUT -- "zero columns left" --> S["SOLVED — publish OPTIMAL directly"]
    A -- "empty intersection" --> I["INFEASIBLE"]
    CP -- "activity range misses the bounds" --> I
    FR -- "frozen row violated" --> I
    B -- "empty column, infinite favourable bound,
nonzero cost" --> U["UNBOUNDED"]
Why it is built this way.

Const input: presolve builds a reduced copy; the caller's model is the checker's ground truth and must survive untouched.

Early outcomes are cheap proofs: four sites prove INFEASIBLE and one proves UNBOUNDED before any factorization exists. The empty-column rule is the one family permitted to report unboundedness (D19's exception): its ray is trivial.

Freezing a row marks bounds that no longer describe it; every later family must refuse a frozen row. The round-order defects D99, D102 and D117 all lived on that edge.

Its own tolerance space: residues are judged in the unscaled model, with windows counted in roundings (ulps), not tunables (D103).

Each reduction pushes a record

Every reduction pushes one record (tag plus the numbers its undo needs) onto an append-only arena; index is always an original index. Families at commit 33bb85d: empty row, singleton row, fixed column, empty column, cost-0 singleton column (D95), free column singleton, implied free column singleton (D105/D106), forcing row, redundant row. Deferred with the count that defers them: duplicates and dominated columns (D101). Refused with six designs measured: bound tightening (D97).

Postsolve — the LIFO replay

flowchart TD
    P["publish (on the reduced model)"] --> E["jm_postsolve_expand"]
    E --> C1["copy surviving rows and columns
through the index maps"]
    C1 --> C2["seed dead rows' activities
from surviving columns
(one compensated carry per row)"]
    C2 --> RP["replay the arena strictly last-in-first-out:
each record restores its variable's value,
status, reduced cost, and the row terms it owes"]
    RP --> F["fold the compensation carry,
normalise −0.0, remember the basis"]
Why LIFO, and why a compensated carry.

Each undo must see the model state its reduction saw; replaying in any other order derives duals from bounds that no longer describe the row (D99). A removed column pays its share into every row it touched, through a Neumaier accumulator; two families short-changed this and D106 made them pay.

Why results are readable only at OPTIMAL.

A stopped solve keeps its basis so the next solve resumes (D70), but its published statuses are zeroed: the stopping point is resumable, never readable as an answer. NUMERICAL_ERROR is the one outcome that keeps no basis.

Why the third arm exists (D19).

Unboundedness is read off a ray, never off an invented bound. A column held by a loan but blocked by a real constraint is an honest refusal, not a wrong UNBOUNDED.

Nine sites write m->solve_status, and two are invisible to a text search for the field name: a whole-struct copy in presolve's compaction and a memset in model_release_arrays. When auditing status behaviour, grep is not enough.

Why the checker is shaped this way.

Original space only — no scaling, no basis, no solver state; it judges the answer against the model the caller loaded, which is why the solver may never rewrite that model (D18).

A failure changes nothing in the library: the checker fills a report and consumers act. In the gate, bench/run.c turns it into the checker= predicate.

The verdict reads declared bounds only (D91): an implied bound's term can be live at a correct optimum, so reading it would reject right answers.

Limit: it never reads a basis status, and it certifies against tolerances, not exactly (SPECS §5).

Why the clear between the two solves (D68).

Without it the second solve would be a warm re-solve, and the determinism check would measure a sequence of calls rather than the solver. The infeasible set expects a refusal (no false optimum) and carries no digest and no checker verdict.

Three rules that decide verdicts.

The digest never fails the gate. Every instance bit-identical to the committed record is the strongest available evidence that a change is a no-op.

A summary line saying 0 regressed means only that no predicate flipped and no instance crossed 2.0x work. Read the per-instance diff; ten commits once reached main under an unmoved summary line (bench/README.md).

Seconds never enter a record or a baseline. Work units are the cost; a time ratio is taken only where units cannot see the change: J=1, minimum over alternating rounds, geometric mean (D45, D93).
