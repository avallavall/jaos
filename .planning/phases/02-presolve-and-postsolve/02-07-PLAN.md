<objective>
The three sets with presolve on, the three sets with presolve off, and only then
the baselines.

Purpose: this is the phase's evidence, and it is a different shape from phase
1's. Phase 1 could require all 139 digests unmoved because its change was
designed to be an observable no-op. Presolve changes the model the simplex sees,
so iteration counts, work units and digests move on the presolve-on path **by
design**. What survives as evidence is the verdicts, the objectives against
Koch's reference, and the checker's acceptance through postsolve — and D-09's
negative control, which is where the digest-identity claim goes instead. With
the reductions compiled out, nothing may have moved at all. That separates
"presolve broke something" from "presolve changed the trajectory", which is
exactly the distinction phase 1's headline could not make.

The three baselines no longer describe the solver: presolve changes the
trajectory and D-14 changed what a work unit counts. Rewriting them is
deliberate, it is its own task, and it happens only after the negative control
is green. A baseline that updates itself records whatever just happened as
correct, which is the one thing it must not do.

Output: five campaign records, a negative-control run diffed against the
pre-phase baselines, three rewritten baselines, and a confirming gate run that
agrees with them instance by instance.
</objective>
