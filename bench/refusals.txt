# The refusals, and what would reopen each one. Read by `make refusals`
# (tools/refusals.sh). One line per refusal:
#
#   D<n> | <script, or MANUAL> | <reopens when>
#
# A script re-tests the refusal on the CURRENT tree and exits 0 when the
# refusal still holds, 1 when its condition is met or its verdict flipped, 2
# when it could not run. MANUAL means the condition is a design or mechanism
# change that a script cannot detect; the text is what to check by hand at a
# milestone boundary. `TODO.md`'s refusals table carries the argument for each
# condition; this file is the executable subset and the list.
#
# `make refusals` REWRITES COMMITTED EVIDENCE. Each script `tee`s into its own
# measurement directory, so running the target overwrites the record that
# refusal was decided on -- 02-118/run-can-move-units.txt and
# 02-119/run-restrict-icount.txt both, as of 2026-08-27. Check `git status`
# after every run and restore what you did not mean to replace. A re-test that
# destroys the reading it is re-testing against is worth less than one that
# does not (found by jaos-measurer while judging D207).
#
# Why this file exists. A refusal is true on the tree that measured it. Trees
# move: D24's premise expired and D94 caught it by luck; D184's reopen
# condition was met on 2026-08-25 and nothing noticed for a day. And a
# refusal made because a change sat "inside the noise" was never a
# measurement of the change, only of the host: tools/icount.sh can now
# resolve what seconds could not, so every refusal of that kind is worth one
# re-run under it.

# A refusal is also only true on the METRIC that measured it, and D225 moved
# one. `tools/icount.sh -m` reports cache misses; instructions have the wrong
# sign for a change whose mechanism is memory-level, because such a change
# does more work in order to wait less. Every refusal below whose reopen
# condition names the instruction count was sorted on 2026-08-30:
#
#   D36   WRONG METRIC. A scatter-form BTRAN trades instructions for
#         locality, and the condition asks whether it "retires fewer
#         instructions than the arithmetic it adds". That question cannot be
#         answered in instructions. Re-ask it in misses.
#   D199  WRONG METRIC, and the script says so itself. Its header: a memset
#         moves 8*nvar bytes while the replacement makes `cleared` scattered
#         stores, so "that is the one case where units and seconds can move
#         in opposite directions". D203 answered it with icount 1.00017.
#         Re-run under -m before this refusal is relied on again.
#   D76   WORTH A RE-RUN. `restrict` changes what the compiler may assume
#         about aliasing, which reaches vectorisation and load counts both.
#         Instructions are defensible here and misses are unmeasured.
#   D61   FINE. Inlining removes calls, so it removes instructions, and the
#         instruction count is what that question is made of.
#   D93   FINE, and already honest: it says "the instruction half".
#
# None of the three has been re-measured. They are listed so the next reader
# does not mistake a standing refusal for one whose evidence still fits the
# question -- which is the D24/D94, D184/D215 failure a third time, in a new
# disguise.
